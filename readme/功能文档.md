# 数据编织平台 · Feature Documentation

> Bilingual feature reference for the in-browser **Data-Weaving** platform demo.
> Generated: 2026-09-09  ·  Stack: Python + FastAPI + uvicorn  ·  Entry: `http://127.0.0.1:8321/`

---
## 1. Overview / Project summary
- A single-page research demo simulating a hospital **data-element circulation** platform in the browser.
- One FastAPI app (`app.py`) with domain modules: `discovery`, `semantics`, `virtualization`, `orchestration`, `governance`, `medsim`.
- Data sources are **in-process simulated databases** (LIS/HIS/PACS/IoT) that self-build into local `data/` on startup and rebuild each restart. No external services.
- The UI is one HTML file (`static/index.html`) with 9 tabs, driven by JSON APIs + client polling (4s panels, 2.5s live ticker).

**Run:** from a project copy set `PYTHONPATH` to the bundled libs, then `python -m uvicorn app:app --host 127.0.0.1 --port 8321`.

## 3. Module Details
### Data Cockpit
- Aggregates platform KPIs and draws data-flow / row-count charts plus a department map; auto-refreshes every 4 s while visible.

### “资源层 — 编织层 — 服务层”分层架构
- Static reference architecture of the weaving pipeline (sources -> active metadata -> semantic layer -> virtualization -> services/governance).

### 主动元数据发现引擎
- 'Active Metadata' engine: fingerprint-based structural + content comparison over five simulated sources each scan cycle, emitting `data_update` events and auto-ingesting schema drift into the catalog.

### 统一语义建模 · 知识图谱
- Entity-relationship / semantic mapping graph linking entities across LIS/HIS/PACS/IoT with confidence-labelled edges.

### 数据虚拟化 · Patient360 联邦视图
- 'Virtual Query' federated Patient 360 read combining multiple sources without physical data movement (zero-copy), plus free-text search over patients and the service catalog.

### 智能化编排与智能调度
- Intelligent orchestration & scheduling (**Part 2**): toggleable governance rules, a task queue with statuses, and an automated `patrol` that scans for anomalies and raises risks feeding Part 4.

### 数据服务目录（要素化方向预览）
- The discoverable **service layer**: register/publish data services and perform governed single-service invocations (authorization + optional dynamic masking).

### 数据服务与流通模式  ·  `dataflow` (Part 3)
> Pipeline: **服务抽象 → 组合供给 → 跨域协同 → 价值反馈（第三部分研究内容）**

- **Service registration & publishing** - wrap data resources + semantic tags + quality attributes into discoverable services (`POST /api/data-services/register`).
- **Service catalog & runtime value** - table of registered/published services with live calls, avg latency and reuse/quality scores.
- **Combinatorial supply (preset flows)** - predefined service chains run end-to-end through governance (`POST /api/data-services/flows/{flow_id}/run`).
- star **Self-composed flow orchestration** (自定义组合供给 · 自由编排) - freely pick any subset of services, set role/purpose/cross_org and run an ad-hoc governed pipeline; each stage returns its own decision + waterfall + provenance. `POST /api/compose-flow`. (New.)
- star **Federation waterfall** - per-source retrieval timing for LAB(LIS)/IMG(PACS+HIS)/VITALS(IoT), built from real row counts and measured latency.
- star **Result provenance overlay** - human-readable lineage of where each returned field came from (source -> transform).
- star **Real-time circulation ticker** - autonomous background calls grow call/value metrics on their own; polled every 2.5 s (`GET /api/circulation/recent`).
- star **Service value leaderboard** (服务流通价值排行) - ranks services by accumulated `value_points` with proportional bars + calls/success-rate/latency, auto-refreshing.

### 安全保障与合规治理  ·  `security` (Part 4)
> Pipeline: **分级分类 → 动态授权 → 全链路审计 → 风险预警处置（第四部分研究内容）**

- **Classification & grading** - data assets graded L1-L4 with masking policies (`GET /api/security/overview`).
- **Dynamic authorization** - role x asset-class x purpose x cross_org decision engine; returns `allow` / `allow_masked` / `deny` with a traceable reason and audit id (`POST /api/security/authorize`, `/mask-preview`).
- **Full-chain audit** - every access/circulation event recorded; browse the recent trail (`GET /api/security/audit`).
- **Risk warning & disposal** - open risks surfaced from orchestration patrol + denied calls, with one-click resolve (`GET /api/security/risks`, `POST /api/security/risks/{rid}/resolve`).

## 4. Recently Added Features (star)
- **Federation waterfall chart** - Per-source retrieval timing for cross-system services; reuses measured latency + real row counts. _(where: `app.py` `_federation_waterfall()` -> `waterfall` field)_.

- **Result provenance overlay** - Human-readable data lineage attached to governed results. _(where: `_wf_provenance()` / injected `result['provenance']`)_.

- **Real-time circulation ticker** - Autonomous background service calls grow call/value metrics without user clicks; 2.5 s poll on Part 3. _(where: frontend `pollCirc()` + `GET /api/circulation/recent`)_.

- **Service value leaderboard (服务流通价值排行)** - Top services ranked by accumulated value points with bars (calls/success-rate/latency). _(where: `#dfLeaderboard`, `renderDfLeaderboard()`, fed by `/api/data-services` stats.value_points)_.

- **Self-composed flow orchestration (自定义组合供给 · 自由编排)** - Ad-hoc multi-service pipeline through the full governance stack; per-stage decision/waterfall/provenance/value. _(where: star new endpoint `POST /api/compose-flow`; composer UI + `runCustomFlow()` in Part 3)_.

- **Color-coded governance decision badges** - Circulation ticker & recent-circulation panel color decisions (allow_masked green / allow cyan / deny red) so Part-4 outcomes surface live on Part 3. _(where: frontend render fns; no new endpoint)_.

**Cross-part integration verified:** running a custom flow in Part 3 feeds the Part-4 audit trail - denied stages raise `denied` counts and risks automatically.

## 6. Run & Verify
- **Start:** from a project copy with `PYTHONPATH=<bundled libs>`: `python -m uvicorn app:app --host 127.0.0.1 --port 8321`. Simulated DBs self-build into `./data` on first start.
- **Smoke checks:**
  - `GET /api/health` -> 200
  - `POST /api/compose-flow {"actor":{"role":"researcher"},"purpose":"research","cross_org":true,"service_ids":["SVC-LAB-RESULT","SVC-FED-QUERY"]}` -> `status: completed`, stages `allow_masked` + masked, `value_points > 0`.
  - Least-privilege check: same call with an L3 analyst over L4 assets (`SVC-PATIENT-360`) -> those stages return `deny` (data class exceeds the role's access ceiling).
- **Note:** live demo copy lives under `medfabric_run/`; original sources remain in `medfabric/`. Wipe `data/` before a clean restart to avoid SQLite sidecar issues.
