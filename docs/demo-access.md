# 医疗业务场景与角色权限

## 业务入口

正常启动项目后，本机环境会初始化医疗业务案例。统一跟踪入口为 `/static/management/work-orders.html`，需求受理和服务目录可从选中记录跳转到对应工单；也可进入 `/static/execution/index.html?tab=delivery` 查看交付。

案例围绕 2026 年 9 月的慢病随访、临床研究、影像检查和检验质量四类业务展开。院区、科室、日期、年龄段和业务状态参与实际筛选与汇总，结果保留不同业务范围的分布差异。需求、规格、方案、合作约定、授权、任务、运行证据、交付和反馈通过业务接口串联；成功结果经过实际执行与签名，拒绝案例经过实际核验。

| 业务 | 推荐身份与路径 | 核对重点 |
| --- | --- | --- |
| 多院区慢病随访月报 | 数据服务中心：需求受理 → 执行方案 → 运行任务 → 结果与凭证 | 确认时间窗、院区与服务项目，受控读取随访状态汇总 |
| 临床研究队列统计 | 临床研究中心：运行任务 → 结果与凭证 | 课题和入组范围进入执行约束，按有效授权下载汇总结果 |
| 影像检查运行统计 | 临床研究中心：结果与凭证 | 按检查类别和签发时段统计，通过 API 方式读取授权结果 |
| 授权期限与主体核验 | 数据服务中心：授权核验 | 查看到期、撤销和主体不匹配的拒绝原因，拒绝后不生成结果 |
| 检验报告完整率治理 | 数据服务中心：偏差校准 → 运行证据 → 评价复测 | 基线成功 → 字段缺失 → 质量检查失败 → 暂停 → 修复 → 同范围复测 |
| 医院数据目录服务 | 医院数据中心：服务目录与发布 → 运行证据 → 评价复测 | 核对发布验证、待修正服务、实际调用评价与稳定性复测 |

需求与服务、执行与交付、安全与治理的侧栏目录及页内子目录，使用与业务链相关联的记录。需求方和供给方各有自己权限范围内的评价与复测。

四张业务表共 2,394 条记录：慢病随访 693 条、科研队列 396 条、影像检查 837 条、检验报告 468 条。统计结果按业务记录次数计数，不解释为去重患者数。初始化生成 6 条需求、5 份确认规格、5 个方案、11 个任务、10 份交付和 3 组复测；首次生成约需一分钟，后续启动直接使用既有记录。

## 三类权限

- **可查看、可操作**：显示目录和适用操作。按钮继续受记录归属、状态、授权和交付方式限制。
- **可查看、不可修改**：保留目录、详情、历史和核验等允许的查看操作，隐藏修改操作。侧栏、标签和按钮不附加“只读”字样，权限表统一放在平台说明中。
- **不可查看**：隐藏侧栏目录及页内切换入口；直接打开地址显示“无查看权限”，对应接口返回 403。

| 模块 | 平台方 / 数据服务中心 | 供给方 / 医院数据中心 | 需求方 / 临床研究中心 | 审计方 / 数据合规岗 |
| --- | --- | --- | --- | --- |
| 协作工单 | 查看全部工单、补充协调说明 | 查看本方服务的使用摘要、参与本方服务沟通 | 跟踪本人申请全流程、补充说明 | 查看工单及协作记录 |
| 需求受理 | 维护、确认规格 | 不可见 | 维护自己的需求，规格只读 | 只读 |
| 服务目录与发布 | 维护、发布、停用 | 维护自己的服务、申请验证；发布状态由平台管理 | 只读可见的已发布服务 | 只读 |
| 元数据维护 | 维护 | 只读可见目录 | 只读可见目录 | 只读 |
| 执行方案、运行任务、触发调度 | 操作 | 不可见 | 操作自己的记录 | 只读 |
| 执行流程 | 只读 | 不可见 | 自己方案的流程只读 | 只读 |
| 逻辑视图 | 新建、查看 | 新建、查看自己的记录 | 新建、查看自己的记录 | 只读 |
| 结果与凭证 | 查看凭证；按交付主体和授权读取结果 | 不可见 | 按授权操作自己的交付 | 查看凭证、验签，不读取结果内容 |
| 访问授权 | 签发、撤销 | 自己的授权只读 | 自己的授权只读 | 只读 |
| 授权核验、运行证据 | 只读 | 与自己关联的记录只读 | 与自己关联的记录只读 | 只读 |

权限定义统一放在 `static/shared/access-policy.json`。页面通过 `/api/access` 获取当前身份的权限；后端使用同一份定义并额外核对记录归属。隐藏按钮不是接口授权的替代品。

## 协作工单

工单以需求编号为主键，直接关联已确认规格的固定版本、方案版本、授权核验、任务、交付、质量处置及评价，不另外维护一套可任意点击为完成的状态。改版后的需求不会借用历史交付显示完成；重试保留失败记录，交付后的读取拒绝仍作为异常保留。

- 需求方只看本人的申请，可查看申请、确认、执行、交付、异常与反馈五个环节，跳转到原业务页面办理或读取授权结果。
- 供给方查看与本方服务相关的需求用途、申请部门、调用进展和质量反馈；区分申请使用、已编入方案和已调用。原始需求附件、查询约束、其他服务节点和交付内容不随工单摘要开放。
- 协作说明按服务划分沟通范围。供给方仅进入本方服务频道；需求方与平台也可保留内部说明。审计方可查阅，不能发送协作说明。
- 质量评价可选择整个任务或已调用的具体服务。跨供给方方案的整体评价不展开给各服务供给方；指定服务的评价经过固定方案版本与实际调用证据校验后，进入对应供给方工单。供给方退出当前需求范围后，只能查看其历史参与版本。
- 原有业务页面继续负责确认、授权、执行、交付与治理操作；协作说明不会自动改变业务状态。此版集中追踪与沟通，尚未引入人员派单、工单关闭审批、超时催办或站外通知。

新增独立案例批次 `HEALTHCARE-WORK-ORDERS-V1`：

| 案例 | 可验证的业务过程 |
| --- | --- |
| 代谢风险课题用数前目录覆盖核验 | 需求方申请、供给方说明口径、平台确认、三方约定、到期授权拒绝、有效授权执行、交付和使用评价 |

## 初始化、替换与数据来源

- 新版初始化记录为 `HEALTHCARE-SCENARIOS-V2`，实现位于 `platform_core/healthcare_scenarios.py`。重复启动跳过已有案例，不重置编辑、结果销毁状态或日期。
- 上一版案例按生成清单归档后替换；保留用户新增、修改的记录及其依赖。替换不修改原医疗来源文件，也不按名称包含某个词来批量删除记录。
- 业务数据来自独立、确定性生成的合成数据集，不包含真实患者身份，也不能当作真实机构的业务统计。该来源说明保留在开发文档和内部初始化清单；页面中的名称、说明、评价与指标采用正常医疗业务语言。
- 常规详情将本机主体标识显示为业务部门，并省略内部初始化标记。“查看完整记录”保留原始主体值和内部字段，授权、签名、质量检查与业务限制不会因展示转换而改变。
- 触发器默认停用，避免启动后持续产生任务。设施心跳仍按真实时间失效，可以手动发送心跳。
- 案例授权期限为生成之日起 30 天，项目和数据使用约定周期为 90 天；保留独立的过期和撤销记录，到期后不会自动续期。
- 质量复测按实际测量决定“关闭”或“观察中”，不强行制造成功结论。
- 设置 `MEDFABRIC_DEMO_SCENARIOS=0` 可关闭自动初始化；不会删除已写入的案例。非 demo 环境不会初始化这些数据。
- 四种身份仍由本机选择器切换，不是真实登录。真实身份认证、跨机构信任、外部授权及第三方存证尚未接入；旧版独立页面也还需要统一身份迁移。

- `node --test test_access_ui.js test_permission_guide.js test_work_order_ui.js test_graph.js test_exploration.js test_cockpit_model.js`：48 项通过，覆盖权限表、菜单与操作可见性、工单筛选、链接、消息范围、分页及详情展示。修改的 JavaScript 模块另做显式源码解析，四种身份已完成页面核对。
- 本机实测完成旧版 237 条业务对象的归档替换；四种身份的可见业务子页均有数据，页面已核对需求、规格、授权期限及三院区随访汇总。
