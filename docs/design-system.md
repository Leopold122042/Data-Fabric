# MedFabric 新版工作台视觉规范 · 第一版

适用于医院管理人员的数据总览，以及后续数据资源、患者全景、数据服务、运行与治理、安全审计页面。样式统一放在 `static/workspace.css`，只作用于 `body.mf-app`，不影响旧版。

## 设计目标

- 首屏先呈现管理人员需要核查的重点，再进入分布、来源和运行明细。
- 沿用 Metabase 式的白色卡片、浅色页面、单一主蓝和克制的边框。图表用颜色区分数据，装饰不争夺注意力。
- 所有原有功能与字段仍有入口。折叠改变阅读层级，不改变统计口径、权限或业务行为。
- 颜色只作辅助。状态必须有文字，指标必须能找到口径、时间范围与来源。

## 统一设计变量

| 类别 | 变量与取值 | 使用规则 |
|---|---|---|
| 主色 | `--mf-brand: #509ee3`；`--mf-brand-strong: #246aab`；`--mf-brand-soft: #eaf3fc` | 主蓝用于图表；较深蓝用于文字链接与白字主按钮；浅蓝用于当前导航与选中态。`--mf-blue` 为主蓝兼容别名 |
| 页面 | `--mf-background: #f6f8fb`；`--mf-surface: #fff`；`--mf-surface-subtle: #f8fafc` | 白卡承载内容，浅底区分补充信息，不堆叠阴影 |
| 文字 | `--mf-text: #273849`；次级 `#5e7082`；辅助 `#637486` | 正文清晰，辅助说明在页面浅底对比度约4.51:1；不用过浅灰承载关键数据 |
| 边框 | `--mf-border: #e3e9ef`；强边框 `#cbd7e1`；1px | 弱边框用于卡片、表格；强边框用于输入与操作控件 |
| 状态 | 成功 `#237954`；待核查 `#91600b`；失败 `#b83d45` | 使用各自浅底与明确文字，不能仅靠红绿表达 |
| 五源图表 | HIS `#509ee3`，LIS `#67b4a0`，PACS `#a28bc5`，EMR `#e5b567`，IoT `#708cad` | 五源颜色在各页面固定；其他分类图优先使用同一主蓝 |
| 字号 | 正文14px，辅助最小12px，标题26px，指标30px | 常规字重400，操作/标签500，标题/指标600 |
| 间距 | `--mf-space-1/2/3/4/6/8` 对应4/8/12/16/24/32px | 控件内部使用小间距；模块之间20–24px；页面内容区28px |
| 圆角 | `--mf-radius: 7px` | 卡片与控件统一；标签可用4px；对话框10px |
| 布局 | `--mf-sidebar-width: 196px`；内容最大1400px | 侧栏随页面滚动，避免固定层遮挡；主区域允许收缩 |

字体优先系统字体，中文回退到苹方、微软雅黑或 Noto Sans CJK SC。数值使用等宽数字，不强制等宽字体。

## 组件契约

| 组件 | 类名 | 内容与使用要求 |
|---|---|---|
| 工作台骨架 | `.mf-shell`、`.mf-sidebar`、`.mf-main`、`.mf-topbar`、`.mf-content` | 左侧导航、顶部路径、内容区；当前导航用 `.is-active` 并同时设置 `aria-current` |
| 页标题与工具栏 | `.mf-heading`、`.mf-subtitle`、`.mf-toolbar` | 标题表达业务主题；说明给出范围；筛选、刷新和版本入口分组 |
| 操作 | `.mf-button`、`.mf-button-primary`、`.mf-link` | 每个区域只突出必要主操作；次级操作使用描边按钮或文字链接 |
| 状态 | `.mf-badge.is-success/is-warning/is-danger/is-muted`、`.mf-alert` | 小圆点加状态文字；阻断或过期状态可用横向提示；未知不得显示成功 |
| 首屏指标 | `.mf-stats`、`.mf-stat`、`.mf-stat-label/value/meta` | 四列、四项重点；说明保留单位、范围和时点；可钻取时使用真实 `button` |
| 内容面板 | `.mf-panel`、`.mf-panel-head/body/footer` | 头部标题与局部操作，主体放图表或表格，底部说明口径 |
| 图表 | `.mf-chart-wrap`、`.mf-chart`、`.mf-chart-legend`、`.mf-chart-tooltip` | 图高260px；固定来源颜色；显示刻度、单位、图例；交互图例使用按钮和 `aria-pressed` |
| 科室分布 | `.mf-dept-bars`、`.mf-dept-row`、`.mf-bar-name/track/fill/value` | 整行可点击，名称与数值直读；选中后保留明显状态及科室明细 |
| 局部选择 | `.mf-segment`、`.mf-selection-detail` | 互斥切换使用 `aria-pressed`；选中内容需保留文字说明，避免仅改变颜色 |
| 图表选项与辅助 | `.mf-chart-options`、`.mf-sr-only`、`.mf-grid-equal` | 选项随宽度换行；辅助标签供读屏读取；同权重面板可使用等宽双列 |
| 表格与记录 | `.mf-table-wrap`、`.mf-table`、`.mf-list-row` | 大表仅表格区域横滚；列表不嵌套固定高度滚动；缺失值明确标注 |
| 次级信息 | `.mf-secondary-stats`、`.mf-flow`、`.mf-disclosure` | 运行量、六阶段流转与技术明细放在次级区；折叠入口说明其中内容 |
| 输入 | `.mf-filter` | 使用原生输入或下拉框，配置可访问名称；只呈现实际生效的筛选 |
| 详情对话框 | `.mf-dialog`、`.mf-dialog-head/body/close`、`.mf-definition-grid` | 使用原生 `dialog.showModal()`，标题关联，明确关闭，Esc退出；关闭后焦点回到入口 |
| 技术明细 | `.mf-code` | 长路径或JSON可换行，避免撑宽页面；业务解释在技术内容之前 |
| 空状态与页脚 | `.mf-empty`、`.mf-page-footer` | 说明当前无数据、失败或范围限制；不能使用看似正常的默认数字 |

所有隐藏内容统一使用 `hidden` 属性。CSS 不负责计算、网络请求或权限判断，避免样式改动改变功能。

## 布局与响应式

- 桌面：196px侧栏，四列重点指标，两列主体图表（1.2:1），表格采用行式布局。
- 850px及以下：侧栏缩至162px，图表逐一堆叠，指标改为两列，流转阶段改为三列。
- 650px及以下：导航移到顶部并换行；内容左右留16px；表格仅在自身容器横向滚动。
- 380px及以下：页面留12px，六阶段改为两列，长字段及明细定义列表换行；不能出现整页横向滚动。
- 触屏：主要按钮、筛选、分段控件、导航、科室行等目标不小于44px高。
- 打印：隐藏导航和浮层，主体单列，保留图表颜色，明细展开显示，避免整卡被分页切断。

## 状态、可访问性与验收约定

1. 加载、空数据、失败、权限拒绝、数据过期各有文字；成功仅表示已确认的状态，不泛化为“正常”。
2. 数据值、时间范围、样本范围与口径必须在本区域或明确可见的详情入口中找到。
3. 键盘能到达筛选、切换和详情入口；焦点清晰，选中态有语义属性；原生对话框管理焦点。
4. 图表采用标签、数值、图例共同表达，异常用文字辅助颜色；技术标识不得替代业务名称。
5. 默认无渐变、无装饰动画；尊重减少动态效果的系统偏好。
6. 每次新增模块沿用现有组件；先复用变量与布局，确需特殊样式时限定在该模块，避免影响其他页面和旧版。

此规范定义视觉与交互约束，数据正确性、功能保留及权限验收以本轮开发阶段清单和改版前后对应表为准。
